# WordPress の記事を AI に伝わりやすい形にする「OD AI Content」でできること

ChatGPT をはじめとする生成 AI が身近になり、「自分の Web サイトにある情報も、AI に正しく理解してもらえるようにしたい」と考える機会が増えてきました。

ただ、普段僕たちがブラウザーで見ている Web ページは、本文だけで作られているわけではありません。ヘッダーやメニュー、関連記事、装飾用の HTML など、ページを見やすくするためのさまざまな情報が含まれています。

人が見るうえでは必要なものですが、本文を取り出して再利用したいツールにとっては、少し複雑な構造になっている場合があります。

そこで作ったのが、WordPress プラグイン「OD AI Content」です。

この記事では、OD AI Content がどのようなプラグインなのか、導入すると何ができるようになるのかを、なるべく専門用語をかみ砕きながら紹介します。

## OD AI Content とは

[OD AI Content](https://github.com/Olein-jp/od-ai-content) は、WordPress で公開している投稿や固定ページを、通常の HTML に加えて Markdown でも配信できるようにするプラグインです。

Markdown は、文章の見出しやリスト、リンクなどを、比較的シンプルな記号で表せる形式です。たとえば、次のように書くと見出しとして扱われます。

```markdown
# 記事のタイトル

## 見出し

- 項目1
- 項目2
```

普段の Web ページと比べると、レイアウトや装飾に関する情報が少なく、文章の構造を把握しやすいのが特徴です。

OD AI Content を有効にしても、読者がブラウザーで見るページのデザインが Markdown に置き換わるわけではありません。これまでどおりの Web ページを残したまま、その記事の「別の表現」として Markdown 版を追加します。

イメージとしては、同じ内容の通常版とテキスト中心版を、用途に応じて取り出せるようにする感じです。

なお、プラグイン名に「AI」と入っていますが、このプラグイン自体が生成 AI を使って文章を書き換えたり、要約を作ったりするわけではありません。Markdown の生成に外部の AI サービスや API キーは必要なく、WordPress にある公開コンテンツを別の形式に整えることが役割です。

生成される Markdown の状態は、WordPress 管理画面の「Markdown診断」で確認できます。記事ごとに診断とプレビューを行えるほか、投稿一覧から複数の記事をまとめて診断することもできます。

## OD AI Content でできること

### 公開記事に Markdown 版の URL を用意できる

プラグインを有効にすると、対象となる投稿や固定ページに Markdown 版の URL が追加されます。

たとえば、通常の記事 URL が次のものだったとします。

```text
https://example.com/blog/example/
```

この場合、Markdown 版は次の URL で取得できます。

```text
https://example.com/blog/example/index.html.md
```

これは、`llms.txt` の提案で示されている、ファイル名のない URL には `index.html.md` を追加する方法に沿った形です。[llms.txt の提案](https://llmstxt.org/)でも、Web ページに対応する簡潔な Markdown 版を用意する方法が紹介されています。

記事を更新すると、Markdown 版にも現在の内容が反映されます。Markdown ファイルを別に作成し、記事を修正するたびに手作業で書き直す必要はありません。

### 記事の本文だけでなく、出典を判断するための情報も含められる

生成される Markdown の先頭には、次のような情報が付け加えられます。

- 記事タイトル
- 通常のページの URL
- 言語
- 著者
- 公開日時と更新日時
- 投稿タイプ
- カテゴリーやタグなどの分類
- 抜粋がある場合は、その説明文

そのあとに記事タイトルと本文が続きます。

本文だけを抜き出すのではなく、「何という記事なのか」「元のページはどこにあるのか」「いつ公開・更新されたのか」といった情報も一緒に渡せるわけです。

とくに、通常のページの URL を `canonical_url` として含めている点は大切だと考えています。Markdown 版だけを見たツールでも、元になった Web ページをたどりやすくなるためです。

### ブロックエディターの内容を、意味のある形で変換できる

WordPress のブロックエディターでは、見出し、段落、画像、ボタンなどを「ブロック」として組み合わせて記事を作ります。

OD AI Content は、主に次のようなコアブロックを Markdown に変換します。

- 見出し、段落、リスト、引用
- 表、コード、画像
- 詳細、埋め込み
- ボタン、メディアとテキスト
- グループ、カラム、カバー

たとえば、ボタンは見た目の装飾ではなく、ボタンに書かれた文字とリンク先を残します。YouTube などの埋め込みも、埋め込み先を確認できるリンクとして出力します。

一方で、ナビゲーション、ソーシャルリンク、スペーサー、クエリーループは、初期状態では Markdown に含めません。記事本文ではない情報や、ページごとに繰り返されやすい情報を減らすためです。

対応を個別に用意していないブロックは、表示用に生成された HTML から Markdown への変換を試みます。そのため、見慣れないブロックだからといって、内容をそのまま捨てる設計にはしていません。

ただし、使用しているテーマやプラグイン独自のブロックによっては、意図した形に変換されない可能性があります。そのような箇所は、管理画面の診断とプレビューで確認できます。

サイトを開発する人向けには、独自ブロックの扱いを調整する方法も用意しています。装飾専用などの理由で出力しないことが決まっているブロックは「意図的な除外」として登録できます。また、HTML からの変換結果を確認済みのブロックは「検証済み」として登録し、注意の対象から外せます。

これは警告を一律に隠す機能ではありません。登録していない独自ブロックは「未検証の HTML フォールバック」として注意に残ります。テーマやブロックプラグインの更新で出力が変わることもあるため、登録したあとも、更新時にはプレビューを確認しておくと安心です。

### Markdown の状態を診断してプレビューできる

投稿のブロックエディターにある「OD AI Content」パネルを開くと、「Markdown診断」の結果と「Markdownプレビュー」を確認できます。

診断では、主に次の項目を調べます。

- Markdown 文書を生成できるか
- 記事タイトルや通常ページの URL など、必須の情報が含まれているか
- 記事タイトルと一致する大見出しが1つだけあるか
- Markdown の本文が空になっていないか
- 見出しの階層が途中で飛んでいないか
- 変換時に除外されたブロックがあるか
- 未検証の HTML フォールバックで変換されたブロックがあるか

診断結果は、「正常」「注意」「エラー」「除外」「未診断」のいずれかで表示されます。総合的な診断結果に加えて、各項目は次の3つに分けて確認できます。

- 確認が必要な項目
- 情報
- 正常な項目

「エラー」や「注意」の原因は「確認が必要な項目」へまとめて表示されます。たとえば、本文が空になっている場合は、「エラー」という総合結果だけでなく、「Markdown本文が空です」という問題点まで確認できます。

一方、「Markdown文書を正常に生成できました。」などの正常な項目は、初期状態では折りたたまれています。確認したいときには開けますが、普段は問題のある項目を先に読める構成です。色だけで判断するのではなく、「エラー」「注意」「情報」「正常」というラベルも一緒に表示します。

「注意」が表示された場合でも、Markdown をまったく生成できていないとは限りません。たとえば、プラグイン独自のブロックが専用の変換処理ではなく、HTML から Markdown へ変換されている場合に「注意」となります。この場合は「Markdownプレビュー」を読み、本文やリンクが意図した形で残っているかを確認すると良いでしょう。

「エラー」は、本文が空になっている、必要な情報が不足している、見出しに問題があるなど、生成結果を見直したい状態です。「除外」は、その記事が Markdown 出力の対象外に設定されていることを表します。

記事を編集中の診断結果は、最後に保存した内容をもとにしています。未保存の変更がある間は、そのことを案内するメッセージが表示され、「診断を再実行」は一時的に押せなくなります。投稿を保存すると、保存した最新の内容で診断が自動的に更新されるため、保存直後にあらためてボタンを押す必要はありません。

投稿一覧には「OD AI Content」という列があり、記事ごとの診断状態をまとめて確認できます。正常は緑、注意は黄土色、エラーは赤、除外はグレー、未診断は青で表示されます。色だけに頼らず、アイコンと文字も一緒に表示されるため、一覧を眺めたときにも状態を判断しやすくなっています。

公開中で Markdown 出力の対象になっている記事には、「Markdownを表示」というリンクも表示されます。編集画面を開かなくても、実際に配信されている Markdown を投稿一覧から確認できます。

### 複数の記事をまとめて診断できる

記事数が増えてくると、1記事ずつ編集画面を開いて診断するのは少し大変です。そのようなときは、投稿一覧から複数の記事を選び、まとめて診断できます。

操作の流れは次のとおりです。

1. WordPress 管理画面で投稿や固定ページの一覧を開く
2. 診断したい記事にチェックを入れる
3. 「一括操作」から「OD AI Contentの診断を実行」を選ぶ
4. 「適用」を押す

選んだ記事は一度にすべて処理するのではなく、WP-Cron を使って少しずつバックグラウンドで診断されます。一括診断を始めると、最初に受け付けた件数と対象外になった件数が表示されます。処理中は、待機中、処理中、完了、失敗の件数を確認できます。ひとつの記事で診断に失敗しても、残りの記事の処理は続きます。

診断が完了すると、完了後の件数が一度だけ表示され、その後は通知が自動的に消えます。一括診断を行っていない普段の投稿一覧に「待機中：0」などの状態が残り続けることはありません。

バックグラウンド処理なので、診断がその場ですべて完了するとは限りません。[WordPress の公式ドキュメント](https://developer.wordpress.org/plugins/cron/)にもあるように、WP-Cron は継続的に動く仕組みではなく、通常はページが読み込まれたタイミングで実行されます。アクセスの少ないサイトや WP-Cron が適切に起動されない環境では、完了まで時間がかかる可能性があるため、少し時間を置いて投稿一覧を再読み込みして確認してください。

この診断は、生成した Markdown の構造や変換方法を確認するためのものです。文章の内容が正しいか、AI が実際にどのように解釈するかまで判定したり、問題を自動修正したりする機能ではありません。診断結果を入口にして、最後はプレビューを自分の目で確認するのが安心です。

### サイト内の重要な記事を `llms.txt` にまとめられる

OD AI Content は、サイトのルートに次の URL を用意します。

```text
https://example.com/llms.txt
```

`llms.txt` は、AI や関連ツールがサイトの概要と参照先を見つけやすくするための、Markdown 形式の案内ファイルとして提案されているものです。サイト名や説明に加えて、記事のタイトル、Markdown 版の URL、短い説明を一覧にできます。

よく知られている `robots.txt` や XML サイトマップと似て見えるかもしれませんが、役割は同じではありません。[llms.txt の公式提案](https://llmstxt.org/)では、サイトマップの代わりではなく、AI が必要な情報を見つけるための、より絞り込まれた案内として説明されています。

OD AI Content では、すべての記事を無条件で並べるだけでなく、次の2つの運用方法を選べます。

- 対象の投稿タイプにある公開コンテンツを、既定で `llms.txt` に含める
- 投稿ごとに、`llms.txt` へ含めるかどうかを選ぶ

個人的には、サイト内のすべての記事を並べるよりも、まずはプロフィール、サービス案内、よく読まれている記事など、サイトを理解するうえで大切なページから選ぶ方法が扱いやすいと感じています。

各記事には最大280文字の短い説明も設定できます。未入力の場合は、記事の抜粋、本文の先頭部分の順に使われます。

### 公開したくない内容は除外できる

設定画面では、Markdown 出力を有効にする投稿タイプを選べます。初期状態の対象は投稿と固定ページです。

さらに、ブロックエディターの「OD AI Content」パネルから、記事ごとに「このコンテンツをMarkdown出力から除外」を設定できます。

除外した記事では、Markdown 版の URL にアクセスしても内容は表示されず、`llms.txt` の掲載候補にもなりません。

また、次のコンテンツはもともと Markdown 出力の対象外です。

- 下書き
- 非公開の記事
- パスワードで保護された記事
- 設定で対象にしていない投稿タイプ

つまり、このプラグインは WordPress ですでに公開されている情報を、別の形式でも提供するためのものです。非公開情報を AI へ送信するための仕組みではありません。

### Markdown 版があることを機械的に伝えられる

通常の HTML ページには、その記事に Markdown 版があることを示す `alternate` 情報を追加します。

これは、ページを訪れた対応ツールに対して、「同じ内容の Markdown 版はこちらにあります」と伝えるための目印です。ブラウザーの見た目にはほとんど影響しないため、普段サイトを見ている読者が操作を覚える必要はありません。

Markdown 版には、元の記事を示す情報と `noindex` の指示も付けています。Markdown 版を検索結果へ別ページとして掲載してもらうことより、通常の Web ページを本来のページとして扱いつつ、必要なツールには読み取りやすい形式を提供することを重視しています。

## インストールと最初の設定

2026年7月30日時点の最新版は、[バージョン0.5.0](https://github.com/Olein-jp/od-ai-content/releases/tag/0.5.0)です。WordPress 6.9 以降、PHP 7.4 以降に対応しています。

現時点では WordPress.org のプラグインディレクトリから検索してインストールする形式ではないため、GitHub のリリースページから配布用の `od-ai-content.zip` をダウンロードして利用します。

WordPress 管理画面からの流れは次のとおりです。

1. GitHub のリリースページから `od-ai-content.zip` をダウンロードする
2. WordPress 管理画面の「プラグイン → プラグインを追加」を開く
3. 「プラグインのアップロード」を押す
4. ZIP ファイルを選び、インストールして有効化する
5. 「設定 → OD AI Content」を開く
6. 「Markdown代替表現を有効化」と、対象にする投稿タイプを確認する

ZIP ファイルを管理画面からアップロードする方法については、[WordPress.org の「プラグインの管理」](https://ja.wordpress.org/support/article/managing-plugins/)でも案内されています。

`llms.txt` を運用する場合は、続けて次のどちらかを選びます。

- 「個別設定のないコンテンツをllms.txtに含める」を有効にし、必要のない記事を個別に外す
- 全体の既定値は無効のままにし、掲載したい記事だけを個別に選ぶ

設定後は、対象となる投稿の編集画面を開き、「Markdown診断」と「Markdownプレビュー」を確認します。記事が複数ある場合は、投稿一覧の「OD AI Content」列と一括診断を使うと、サイト全体の状態を確認しやすくなります。

公開記事の URL の末尾に `index.html.md` を追加するか、投稿一覧の「Markdownを表示」を押すと、実際に配信されている Markdown 版を開けます。あわせて、サイトの `/llms.txt` も開いて、意図した記事と説明文が掲載されているかを見ておきましょう。

なお、GitHub で新しいリリースが公開された場合は、WordPress 標準のプラグイン更新画面に更新通知を表示できる仕組みも備えています。

## どのようなサイトに向いているのか

OD AI Content は、次のようなサイトで検討しやすいと思います。

- ブログやオウンドメディアに、蓄積した記事がある
- サービス内容や活動内容を、文章で詳しく発信している
- 製品マニュアルや技術資料を WordPress で公開している
- 公開情報を、外部の検索・要約・ナレッジツールから再利用しやすくしたい
- `llms.txt` や Markdown での情報配信を小さく試してみたい

反対に、会員限定サイトなど、非公開情報が中心のサイトには用途があまりありません。また、EC サイトの商品価格や在庫、複雑なカスタムフィールドの情報を専用形式で出力する機能は、現時点では備えていません。

テーマや独自ブロックによる表現を細かく再現したい場合も、追加の調整が必要になる可能性があります。開発者向けには、ブロック変換やメタデータ、最終的な Markdown 文書を調整するためのフィルターが用意されています。意図的に出力しないブロックと、HTML からの変換を確認済みのブロックも登録できます。

## 導入前に知っておきたいこと

一番大切なのは、OD AI Content を導入しただけで、ChatGPT などの回答に必ず掲載されたり、検索順位が上がったりするわけではないという点です。

`llms.txt` は、2024年9月に公開された提案であり、従来の Web 標準を置き換えるものではありません。どの AI やツールが、いつ、どのように利用するかは、それぞれのサービス側の実装に左右されます。

OD AI Content が行うのは、公開している情報に、機械が見つけやすく読み取りやすい入口を追加するところまでです。記事そのものの正確さ、更新、サイトの信頼性、クローラーに対するアクセス方針などは、引き続きサイト運営側で考える必要があります。

また、`llms.txt` はクローラーのアクセスを許可・拒否するためのファイルではありません。クローラーごとの扱いを決めたい場合は、各サービスの仕様を確認したうえで、`robots.txt` などを別途検討してください。

## まとめ

OD AI Content は、WordPress で公開している記事に、AI や外部ツールが扱いやすい Markdown 版を追加するプラグインです。

主な役割を短くまとめると、次の4つになります。

- 公開記事を Markdown でも取得できるようにする
- Markdown 版に、元記事や公開日などの情報を添える
- Markdown の構造やブロックの変換状態を、記事ごとまたは一括で診断する
- 重要な記事を `llms.txt` で案内できるようにする

人に読んでもらうための通常の Web ページはそのまま残し、その横に機械向けの入口を用意する。個人的には、そのくらいの距離感から AI に向けた情報整備を始められるのが、このプラグインの良いところだと考えています。

まずはテスト環境や小さなサイトで、数記事の Markdown 版を確認するところから試してみてください。今ある WordPress のコンテンツを、これからどのように届けていくか考える際の参考になれば嬉しいです。
